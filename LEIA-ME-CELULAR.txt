DISCÓRDIAHUB NO CELULAR (ANDROID E iOS)
=======================================

É o mesmo sala.html do computador, dentro de um aplicativo nativo feito com o Capacitor.
Quem está no Windows, no Android e no iPhone entra na MESMA sala (o protocolo não mudou).

O QUE FUNCIONA NO CELULAR
- Voz, câmera, fotos, chat, emojis, player de música e vídeo, tema claro/escuro.
- Android: enquanto o microfone ou a câmera estão ligados aparece uma notificação fixa
  ("Microfone ATIVO") e o app continua vivo com a tela apagada ou em outro app.
  O botão Voltar minimiza o app sem sair da call (e fecha janelas abertas antes).
- iOS: modo "áudio em segundo plano" ligado, para a conversa continuar ao sair do app.

O QUE NÃO EXISTE NO CELULAR
- Compartilhar tela: o Android e o iOS não permitem isso a uma página dentro de um app comum.
  O botão some sozinho. Quem transmite tela continua sendo o computador; o celular assiste.
- A opção "segundo plano" das Configurações (no Android o serviço de call já faz isso).
- Atualização automática no iPhone: o iOS não permite. Só pelo TestFlight/App Store (ou reinstalando pelo Xcode).

ANTES DE COMEÇAR
1. Troque o "appId" em capacitor.config.json (ex.: com.seugrupo.discordiahub) pelo seu.
   Faça isso ANTES do primeiro "mobile:init": depois que o app é publicado, o id não muda mais.
2. Node.js 22 ou mais novo (o mesmo do computador).

ANDROID (Windows, Mac ou Linux)
Pela nuvem, sem instalar nada: no GitHub, aba Actions > "Gerar app de celular" > Run workflow.
Em uns 10 minutos o APK fica em Artifacts (DiscordiaHub-Android). Com uma tag (v1.6.1), vai para
a página de Releases junto com o instalador do Windows.

No seu computador:
  1. Instale o Android Studio (traz o SDK e o Java).
  2. npm install
  3. npm run mobile:init        (cria a pasta android/, aplica permissões e o serviço de call)
  4. npm run android:abrir      (abre no Android Studio; botão Run com o celular ligado por USB)
     ou: npm run android:apk    (gera android\app\build\outputs\apk\debug\app-debug.apk)
Para instalar o APK no celular dos amigos: enviar o arquivo e ativar "Instalar apps desconhecidos"
para o app que abriu o arquivo. O APK de debug é assinado com uma chave de teste: serve para o grupo,
mas NÃO serve para a Play Store (ela exige um pacote .aab assinado por você; veja a documentação
do Capacitor, "Deploying to Google Play").

iOS (precisa de um Mac com Xcode 26 ou mais novo)
  1. npm install
  2. npm run mobile:init        (cria a pasta ios/ e aplica as permissões de microfone, câmera e áudio)
  3. npm run ios:abrir          (abre o Xcode)
  4. No Xcode: App > Signing & Capabilities > escolha seu Team (um Apple ID grátis basta para testar
     no seu próprio iPhone; o app expira em 7 dias) e aperte Run com o iPhone ligado.
Para dar aos amigos: só pelo TestFlight (conta de desenvolvedor paga da Apple, US$ 99/ano). Não existe
instalador avulso para iPhone como o .exe do Windows. O job "ios" do GitHub só confirma que o projeto
compila no simulador; ele não gera nada instalável.

ATUALIZAÇÃO AUTOMÁTICA NO ANDROID
O app confere a última Release do GitHub ao abrir (e a cada 6 horas). Se achar uma versão maior, aparece
o botão "Atualização X.Y.Z disponível: instalar" e um aviso no chat. Também dá para forçar em
Configurações > "Procurar atualização". Ao tocar, o app baixa o APK e abre o instalador do Android.
O Android SEMPRE pede um "Atualizar?" no final: instalação totalmente silenciosa só existe na Play Store.
Na primeira vez ele também pede para liberar "Instalar apps desconhecidos" para o DiscórdiaHub.

Para funcionar (faça uma vez):
  1. package.json > build > publish: "owner" e "repo" com os seus dados (o publicar-github.bat já faz isso).
     O repositório precisa ser PÚBLICO (igual ao atualizador do Windows).
  2. Crie a chave de assinatura:  npm run mobile:chave
     Ele gera discordiahub.keystore e mostra 4 valores. No GitHub: Settings > Secrets and variables >
     Actions > New repository secret, e cadastre: ANDROID_KEYSTORE_BASE64, ANDROID_KEYSTORE_PASSWORD,
     ANDROID_KEY_ALIAS e ANDROID_KEY_PASSWORD.
     Por quê: o Android só atualiza por cima se o APK novo tiver a MESMA assinatura do instalado. Sem a chave
     fixa, cada build do GitHub sai com uma chave aleatória e a atualização é recusada.
     GUARDE o discordiahub.keystore e a senha: se perder, todo mundo terá que desinstalar e reinstalar.
  3. Para lançar uma versão nova: suba a versão no package.json e crie a tag (o publicar-github.bat faz
     os dois). O GitHub gera o APK "DiscordiaHub-Android.apk" e o anexa à Release. O número do package.json
     vira o versionName/versionCode do app (1.6.1 -> 10601), então a versão tem que SUBIR a cada release.

ATENÇÃO: quem já tem o APK antigo (feito antes desta mudança, com outra chave) precisa desinstalar e instalar
o APK novo UMA vez. Dali em diante as atualizações entram por cima.

NOVA TELA (ESTILO SERVIDOR)
Barra de salas à esquerda, coluna de canais (texto "geral" e voz "Call", com quem está na call embaixo, AO VIVO
para quem transmite e ícone de microfone cortado), chat no centro e lista de membros à direita. Ao entrar na sala
você começa no chat; ao entrar na call a tela vai sozinha para o canal de voz (vídeos e transmissões), com o chat ao
lado. O painel do usuário (canto inferior esquerdo) tem microfone, silenciar call e configurações; a foto de perfil
se troca clicando nela. No celular, o menu (três riscos) abre a coluna de canais. O tema escuro agora é preto,
e o claro continua disponível em Configurações.

PUBLICAR ATUALIZAÇÕES COM DOIS CLIQUES
Depois de editar o app (por exemplo o sala.html), abra o ATUALIZAR.bat. Ele sela o arquivo, roda os testes, sobe a
versão sozinho (1.6.0 -> 1.6.1), envia para o GitHub, cria a tag e espera o GitHub gerar o instalador do Windows e o
APK do Android, avisando quando estiver tudo pronto. Os amigos recebem sozinhos (veja acima). Na primeira vez ele
chama o publicar-github (pergunta usuário e repositório). Opções: ATUALIZAR.bat -Rapido (sem testes),
-Tipo minor (1.6.0 -> 1.7.0), -Versao 2.0.0, -Mensagem "o que mudou".

TRANSMISSÃO DE TELA/JOGO TRAVANDO
Cada amigo que assiste recebe uma cópia separada direto do seu computador, então o upload é dividido: 1080p 60 fps
a 8 Mbps com 3 pessoas seriam 24 Mbps. Agora, ao transmitir, existe "Upload total da transmissão" (padrão 10 Mbps),
que o app divide entre quem assiste e reajusta sozinho quando alguém entra ou sai. No bloco da sua transmissão
aparece ao vivo: fps reais, Mbps e, se houver, "limitado pela internet de envio" ou "limitado pelo processador"
(o chat também avisa). O botão de diagnóstico mostra o codificador em uso.
Dicas: para jogo, use tela inteira sem borda (modo janela sem bordas) ou compartilhe a TELA em vez da janela;
cabo de rede em vez de Wi-Fi; codec H.264 (placa de vídeo); 1080p 30 fps ou 720p 60 fps para 3 ou mais pessoas.

RUÍDO, TECLADO E ECO
- Configurações > "Processamento do microfone": agora o padrão é "Com cancelamento de eco". O modo "Jogos"
  desliga o cancelamento de eco (só use com fone, senão quem está na call ouve a própria voz de volta).
- Configurações > "Filtro extra de ruído (teclado, mouse)": Normal (padrão), Forte ou Desligado. É uma porta de
  ruído com antecipação de 40 ms: só deixa passar voz sustentada, então estalos curtos (teclas, mouse, copo) são
  abafados e o início das palavras é preservado. Forte é mais rígido e pode cortar voz muito baixa.
- Limite: digitar ENQUANTO fala ainda passa (nenhum filtro desse tipo separa as duas coisas); nesse caso quem
  ajuda é o supressor do navegador, que já fica ligado. Se o filtro não iniciar no aparelho, o app volta sozinho
  ao microfone normal em vez de ficar mudo.
- Para ainda mais qualidade, o próximo passo seria um supressor com rede neural (RNNoise), que exige incluir uma
  biblioteca WebAssembly no projeto.

DEPOIS DE EDITAR O sala.html
  npm run selar     (atualiza o hash da política de segurança, igual ao computador)
  npm run mobile:sync

LIMITES CONHECIDOS (confira num aparelho de verdade; veja o ROTEIRO-DE-TESTE.txt, parte do celular)
- YouTube no iPhone: o app abre a página como capacitor://localhost e o YouTube às vezes recusa
  o player ("erro 153"). Se acontecer, use links de arquivo de áudio/vídeo ou Twitch. No Android a
  página é https://localhost e costuma funcionar.
- iOS em segundo plano: o sistema pode silenciar o microfone de uma página web mesmo com o modo
  áudio. Teste com a tela bloqueada. Se for insuficiente, o caminho é um plugin nativo de WebRTC.
- A política de segurança (CSP) do sala.html é estrita. Em Androids com o "Android System WebView"
  muito antigo, o Capacitor pode não conseguir se injetar; atualize o WebView pela Play Store.
- Os ícones saem do icone.ico (256 px, ampliado). Para ficar nítido, troque assets/icon-only.png
  e assets/icon.png por imagens de 1024x1024 e rode: npx capacitor-assets generate

COMO FUNCIONA POR DENTRO
- capacitor.config.json: nome, id e pasta (www/) do app.
- mobile/build-web.js: copia o sala.html (já selado) para www/index.html.
- mobile/init.js: cria android/ e ios/ com o Capacitor e aplica os ajustes de forma repetível
  (permissões, serviço de call, Info.plist). Pode rodar de novo à vontade.
- mobile/android/: o serviço de call em segundo plano e o atualizador (Java), copiados para o projeto Android.
- mobile/gerar-chave.js: cria a chave de assinatura do APK (npm run mobile:chave).
- sala.html: bloco "Celular" no fim do script (detecta o app, esconde o botão de tela, liga o serviço,
  trata o botão Voltar). No computador e no navegador esse bloco não faz nada.
